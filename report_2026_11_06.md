## Executive summary

### Most important findings

1. **The unified branch is faster than the corresponding valid bases in every final matched branch comparison:** 12 CPU comparisons and 39 GPU comparisons. Each final comparison shows a resolved speedup under the recorded five-pair statistical test.
2. **CPU performance at small blocks is preserved and improved.** Across NPROMA 8, 9, 16, and 32, the unified CPU is **1.2–2.0% faster than pinned main** in the final allocations. An exact, branch-free version of the existing MIX random-generator initialization removed the earlier small CPU slowdown.
3. **Normal GPU execution is faster than its corresponding valid bases at all five tested large blocks:** NPROMA 1,024, 2,048, 4,096, 8,192, and 8,480. Gains are **8.3–13.9% for ACC** and **5.3–7.8% for OMP**.
4. **Tiled GPU execution retains small logical blocks and processes larger execution tiles.** Logical NPROMA 32, 64, and 128 were tested at execution widths 1,024, 2,048, 4,096, and 8,192 columns. Final gains are **1.0–2.4% for ACC** and **5.2–13.8% for OMP**, subject to the reference qualifications below.
5. **The best normal and tiled GPU configurations also beat the updated NPROMA=9 CPU.** Measured speedups are approximately **1.44–1.51× for ACC** and **1.20–1.31× for OMP**, using 64 CPU cores versus two A100 GPUs.
6. **Host and device memory are no more than 5% above their valid bases throughout the final primary GPU matrix.** Many configurations use less memory.
7. **Numerical continuity is strong:** all 39 GPU/base comparisons have exact saved numerical outputs; 292 GPU validation files and 3,888 numerical variables remain exact to the saved pre-change outputs in active columns. The CPU initializer preserves 5.41 million tested SP/DP uniform and Gaussian samples byte-for-byte.

### Two essential qualifications

- **ACC source residency must be matched.** The final tiled ACC wins use `ECRAD_ACC_RESIDENT_FIELDS=1`, which matches the base branch's resident model-source strategy. The default bounded-source mode remains available and has small residual slowdowns at execution widths 1,024/2,048. Radiation scratch is tile-bounded in both modes; resident model storage additionally scales with the total column count.
- **The OMP packed fork is not a valid performance reference.** Its packed path fails numerical validation. Tiled OMP results are therefore compared explicitly with that fork's valid **unbatched, equivalent-execution-width control**, rather than its incorrect packed output.

### Validation headline

- **188/188 CPU CTest tests passed.**
- **14/14 targeted GPU CTest tests passed:** eight ACC and six OMP.
- **Eight compute-sanitizer runs reported zero errors.**
- The inherited large-domain matched-CPU/GPU LW difference remains **0.003814697265625 W/m²**, above the unchanged **0.001 W/m²** threshold. Valid GPU bases share this discrepancy. This report does **not** claim full-domain CPU/GPU numerical agreement.

## Detailed benchmark methodology

### Workload, software, and resources

| Item | Setting |
|---|---|
| Input domain | 16,960 columns × 137 levels |
| GPU decomposition | Two independent ranks, 8,480 columns per rank, one distinct GPU per rank |
| CPU resource | 64 verified physical EPYC 7742 cores / 64 OpenMP threads |
| GPU resource | Two NVIDIA A100-SXM4-40GB GPUs; one physics host thread per rank |
| Compiler | NVHPC 24.5 |
| Performance precision | Single precision only |
| Physics | RRTMG-IFS / McICA; prescribed radii, overlap, and seeds under bit-identity testing |
| Main flags | Release `-O3 -Mrecursive`; GPU `-gpu=cc80` |
| Build controls | Static libraries; FIAT/FIELD_API/NVTX/ROCTX disabled; inline-library extraction disabled consistently |
| Excluded options | No `-gpu=pinned`, fast-math override, or performance-run CUDA stack override |

Input SHA-256: `214b418cccfaac72b2f772eb7a8135ac8e8f8a2719fed96764d6caef51d5cb89`.

The performance executable is the blocked IFS driver, `ecrad_ifs_blocked_sp`. Scientific checks additionally exercise standalone and flat IFS drivers, both precisions, ordinary inputs, and additional physics settings.

### Timing and statistics

1. Five independent process groups are run per configuration, reversing execution order between successive groups.
2. Each process performs six radiation iterations; its first iteration is discarded as warmup.
3. The reported value is the median of the five process-group medians, each based on five measured iterations.
4. For a two-GPU iteration, the rank maximum is used.
5. Timings are synchronized and include required iteration transfers, gathering, and scattering. They exclude initialization, process launch, and NetCDF I/O.
6. In resident-source ACC mode, model allocation is outside the timer, as in the base. **Input refreshes and output downloads remain inside every timed iteration.** Repeats do not skip the required transfers.

Branch comparisons use an exact one-sided paired sign-flip test on log times, with five process-group pairs and `p < 0.05`. Inner iterations are not treated as independent samples. The final primary comparisons show resolved speedups; generally, an unresolved difference alone would not prove equivalence.

Timing ratios are formed only within an allocation. The final three allocations contain 85 configuration records, including repeated CPU controls, representing 69 distinct configurations. They provide **39 primary GPU/base pairs and 12 primary CPU/main pairs**.

## Implementation changes

### Retained architecture

- `ECRAD_GPU_BACKEND=CPU|ACC|OMP|AUTO` selects the implementation. Native CPU coefficient layouts and arithmetic paths are retained alongside accelerator-specific source selection and coefficient-layout adapters.
- Logical NPROMA remains the caller's storage block. Execution tiling combines blocks into larger radiation calls without replacing that model layout.
- The driver owns execution fields/seeds and their lifetimes. Original prescribed seeds or ordinary block-local seed semantics are preserved, including partial tiles.
- Contributor provenance is retained for the ACC and OMP solver and tiling contributions, including Michael Staneker and Paul Mullowney.

### Latest changes and their purpose

| Change | Main source | Purpose |
|---|---|---|
| Scalar weighted SW albedo mapping on ACC | `radiation/radiation_single_level.F90` | Reuse the existing explicit-array helper, retain accumulation order and the ACC zero-weight skip, and remove unused device scratch mappings |
| Layer-parallel ACC coefficient setup | `ifsrrtm/rrtm_setcoef_140gp_gpu.F90`, `ifsrrtm/srtm_setcoef_gpu.F90` | Separate independent layer calculations from ordered column tropopause counts, adapting the tiled ACC donor |
| Ordered, bounded band aggregation | `radiation/radiation_flux.F90` | Sum each band's g-points in original order with scalar accumulators; retain support for interleaved maps and empty bands |
| Reduced host tile footprint | `driver/ecrad_ifs_driver_blocked_gpu.F90` | Avoid faulting unused host input pages; explicitly populate the pressure levels needed for host-side vertical-order checks |
| Block-ordered seed/pressure staging | Same driver | Remove repeated division/remainder while preserving logical-block seeds and active ranges |
| Device-side ACC output scatter | Same driver | Avoid host transposes; use pitched output transfers on the tested NVHPC path, retaining the contiguous-download fallback on other backends |
| Optional resident ACC model sources | Same driver | Match the base's source lifetime; refresh inputs and publish outputs inside each timed model step while retaining tile-bounded radiation scratch |
| Branch-free native MIX initialization | `utilities/radiation_random_numbers_mix.F90` | Eliminate an unpredictable branch using the exactly equivalent Galois shift; preserve the generator, seed mapping, warmup, and output stream |

For the MIX initializer, the original conditional shift is equivalent to a left shift followed by XOR with `175 × bit31(old_state)`. The value 175 is `2 × 87 + 1`, derived from the original polynomial implementation. This is an integer identity, not a change of sampler.

Earlier retained work restored scalar g-point ACC solvers and spectral parallelism, corrected active-range gas initialization and surface mapping, and removed descriptor-heavy LW aggregation overhead. Historical profiling attributed roughly 48 MiB/GPU of excess reservation to CUDA thread-local backing storage; the corresponding helper replacement removed that excess at the measured setting.

Unsuccessful experiments were removed: full g-point scans per band, dense-only wrappers without measurable benefit, 256-lane SW launches, a 32-lane gather, explicit CUDA host registration with a cleanup failure, CPU scratch-interface/vector-cosine trials, and a floating MINSTD reduction irrelevant to the default MIX path. They are not active production options.

- All **39 final GPU/base comparisons** have exact saved numerical outputs, and process-group repeats are exact.
- Controlled/extended GPU versus matched-CPU checks have maximum LW error **0.000335693359375 W/m²** and SW error **0.010986328125 W/m²**, within the existing thresholds of 0.001 and 0.1 respectively.

## Limitations and outstanding work

1. **Resolve or explain the inherited full-domain LW CPU/GPU tolerance miss.** GPU/base equality does not resolve that separate scientific comparison.
2. **The upstream packed OMP reference remains invalid.** The equivalent-width control supports the stated comparisons, but is not evidence that the packed upstream implementation has been repaired or validated.
3. **Source-lifetime choices remain explicit.** Default bounded ACC staging retains the recorded small-width performance gaps against a resident base. Resident mode closes them at the cost of model storage proportional to the total column count.
4. **Coverage is finite.** Performance is SP-only on one domain, one hardware/compiler family, and the listed block/tile sizes. This is not a general scaling study, a DP performance study, or complete solver/ecCKD/FIELD_API/legacy-Makefile validation.
5. **Existing integration limits remain:** blocked IFS execution ignores `istartcol/iendcol`; execution tiles require `COPY_ASYNC` disabled; host-thread/configuration interleaving is not validated. No-derivatives IFS use needs consistent `LAPPROXLWUPDATE`; the tested no-derivatives case is standalone.
6. **Do not generalize historical ACC/OMP parity results to this entire sweep.** The latest acceptance is branch-relative; separate final backend allocations do not establish a new paired ±10% ACC/OMP result for every size.
7. **Release curation still needs review.** The latest runtime/regression changes, benchmark tooling, and development reports are in separate commits. Earlier integration history, including `8896d70`, already contains some benchmark/report files alongside runtime changes; the new split does not rewrite that history. Any subsequent integration with newer main should retain the evidence and repeat the checks appropriate to the changed code.
